# 运行方案

运维入口是 `scripts/run.sh`。四个子命令：`start`、`status`、`stop`、`restart`。无参数等于 `start`。`-h` / `--help` 打印用法后 exit 0。未知子命令 exit 1。不存在 `scripts/start.sh`。

进程读配置是可执行文件目录下的 `config/app.toml`。图片目录优先 cwd 的 `imgs/`（`start` 会 `cd $ROOT`）。`SIGTERM` / `Ctrl+C` 后进程自己最多等 10 秒再退出。

## 路径

| 项 | 位置 |
|---|---|
| 项目根 `$ROOT` | 脚本在 `scripts/` 则父目录，否则脚本目录 |
| PID | `$ROOT/upupt.pid`，不进 git |
| 控制台日志 | `$ROOT/logs/upupt.console.log`，追加进程 stdout/stderr（启动横幅、配置错误、graceful 超时） |
| 业务日志 | `[log]`；cwd 为项目根时即 `logs/upupt.log` |

## 二进制与配置

按顺序取第一个可执行文件：`$ROOT/upupt`，然后 `$ROOT/target/release/upupt`。配置必须是**该二进制同级**的 `config/app.toml`。缺则 start 失败，提示把 `upupt` 放到项目根（与 `config/` 并列），或把 `config/` 拷到 `target/release/`。status / stop 不查二进制、不查配置。

## 判活

PID 文件内容必须是正整数。`kill -0` 失败视为未运行。`/proc/$PID/comm` 可读时必须等于 `upupt`；`/proc/$PID/stat` 状态为 `Z` 视为未运行。PID 被其它进程占用按未运行处理。陈旧 PID 文件：status 只报告、不删；start / stop 清掉。

## start

1. 已在跑：打印 PID，exit 0
2. 清陈旧 PID
3. 确认二进制和其同级 `config/app.toml`
4. `mkdir -p "$ROOT/logs"`，`cd "$ROOT"`
5. `nohup "$BINARY" >> logs/upupt.console.log 2>&1 &`，写 PID
6. 连续 3 秒、每秒看一次仍是 upupt 则成功，打印 PID、二进制路径、控制台日志
7. 中途已退：删 PID，提示看控制台日志和 `[log]`，exit 1

## status

在跑：打印 running 与 PID，exit 0。未跑：打印 not running；有陈旧 PID 文件则附带说明，exit 1。

## stop

未跑：打印 not running，有陈旧 PID 则删除，exit 0。在跑：发 SIGTERM，最多等 12 秒（覆盖进程内 10 秒 graceful）。仍在则 SIGKILL，再等 2 秒。删 PID；仍在则 exit 1，否则打印 stopped。

## restart

先 stop，失败则不再 start；成功后再 start。stop 已等到进程退出，中间不再固定 sleep 1。

## 验证

- `./scripts/run.sh -h` 按 start / status / stop / restart 列出用法，不要求二进制
- 无二进制时 `status` / `stop` 能跑；`start` 失败并提示路径
- 二进制在项目根且同级有 `config/app.toml`：`start` 写 PID，`status` exit 0，`comm` 为 upupt
- 再 `start` 打印 already running，exit 0
- `stop` 后 `status` exit 1，PID 文件消失，端口可重新 bind
- `restart` 换新 PID，接入面能连
- 伪造陈旧 PID：`status` 报 not running 且提到 stale；`start` 覆盖
- 启动失败或成功时，控制台日志里能看到横幅或错误
- 不存在 `scripts/start.sh`
